# 투자나침반 (InvestmentCompass)

실제 돈을 쓰지 않고 주식 거래를 연습해 볼 수 있는 모의투자 프로그램입니다.

주식을 처음 공부할 때는 용어도 낯설고, 매수나 매도를 했을 때 내 자산이 어떻게 바뀌는지 이해하기가 쉽지 않습니다. 투자나침반은 가상자금으로 직접 거래해 보고, 거래내역과 자산 변화를 확인하면서 투자 과정을 익힐 수 있도록 만들었습니다.

거래 기능 외에도 팀원들과 함께 참여할 수 있는 모의투자 대회와 AI 챗봇을 추가했습니다. 챗봇에서는 금융 용어를 질문하거나, 기업 관련 자료를 찾아 요약해 달라고 요청할 수 있습니다.

## 주요 기능

### 모의투자

- 회원가입 시 일반 계좌에 가상자금 1억 원이 지급됩니다.
- 종목명이나 종목코드로 국내 종목을 검색할 수 있습니다.
- 현재가와 기간별 캔들 차트, 거래량을 확인할 수 있습니다.
- 주식을 매수·매도하고 현금 잔액, 보유수량, 평균 매수가, 평가손익을 확인할 수 있습니다.
- 거래내역을 보면서 이전에 어떤 주문을 했는지 확인할 수 있습니다.

현재 거래 기능은 KOSPI와 KOSDAQ의 숫자 6자리 종목코드를 기준으로 구현했습니다. 한국투자증권 API에서 가격을 받아오지만, 실제 증권 계좌에 주문을 넣는 것은 아닙니다.

### 모의투자 대회

관리자가 대회를 만들면 사용자가 참가 신청을 하고, 승인된 참가자에게 대회 전용 계좌가 생성됩니다. 대회에서는 일반 계좌와 별도로 정해진 가상자금을 사용합니다.

- 관리자: 대회 생성·수정·시작·종료·취소, 참가 신청 승인·거절
- 참가자: 대회 신청, 대회 계좌로 거래, 종료 후 최종 순위 확인

관리자 버튼을 숨기는 것만으로 권한을 구분하지 않고, 서버에서도 JWT에 담긴 역할을 확인하도록 했습니다.

### AI 챗봇

질문 목적에 따라 두 가지 모드를 선택할 수 있습니다.

| 모드 | 사용 방법 |
|---|---|
| 일반 설명 | PER, PBR, 분산투자처럼 금융 개념이 궁금할 때 사용합니다. 웹 검색 없이 답변합니다. |
| 자료 조사 | 기업 실적이나 관련 기사를 찾아 내용을 정리하고 싶을 때 사용합니다. 검색 자료를 바탕으로 답변하고 출처를 표시합니다. |

예를 들어 일반 설명에서는 아래처럼 질문할 수 있습니다.

> PER과 PBR은 어떤 차이가 있어?

자료 조사에서는 기업명과 조사할 내용을 구체적으로 적는 것이 좋습니다.

> 삼성전자의 가장 최근 분기 실적을 찾아 매출 변화의 배경을 요약하고 출처를 표시해줘.

답변 아래의 출처를 더블클릭하면 원문을 열 수 있습니다. `이전 질문과 연결`을 체크하면 직전 질문과 답변 일부를 참고해서 이어 답변합니다. 전체 대화를 계속 기억하는 방식은 아니며, 연결 여부는 질문할 때마다 선택합니다.

## 사용한 기술

| 구분 | 기술 |
|---|---|
| 언어 | C# |
| 화면 | .NET 8, Windows Forms |
| 서버 | ASP.NET Core Web API |
| DB | MySQL 8, MySqlConnector |
| 로그인 | JWT, 비밀번호 해시 |
| 종목·시세·차트 | 한국투자증권 API 및 종목 마스터 |

| AI 답변 | 학교에서 제공하는 LLM API |

## 프로그램 구조

화면에서 입력한 내용을 API 서버로 보내고, 서버에서 DB 조회나 외부 API 호출을 처리한 뒤 결과를 돌려주는 구조입니다.

```text
WinForms 화면 → ApiClient → ASP.NET Core API
                              ├─ MySQL: 회원, 계좌, 거래, 대회 정보
                              ├─ KIS: 종목 시세와 차트
                              ├─ Tavily: 웹 자료 검색
                              └─ 학교 LLM: 설명과 분석 답변 생성
```

```text
MockInvestment.sln
├─ MockInvestment.Api
│  ├─ Controllers   요청을 받고 결과를 반환하는 부분
│  ├─ Services      거래, 자산 계산, 대회, AI 처리 로직
│  ├─ Data          MySQL에 SQL을 실행하는 부분
│  └─ Models        요청·응답에 사용하는 데이터 형식
├─ MockInvestment.Client
│  ├─ Forms         관리자와 대회 화면
│  ├─ Controls      캔들 차트
│  ├─ Services      서버 API 호출
│  ├─ Models        화면에서 사용하는 데이터 형식
│  └─ 각 Form.cs    로그인, 거래, 주문, 자산, AI 화면
└─ database         DB 확인 및 대회 기능 추가 SQL
```

## AI 자료 조사는 어떻게 동작하나요?

자료 조사에는 웹 검색 기반 RAG를 사용했습니다. 질문에 맞는 자료를 찾은 뒤, 그 내용을 LLM에 같이 전달해서 답변을 만드는 방식입니다.

```text
질문 입력
  → Tavily로 관련 자료 검색
  → 확보한 본문에서 관련 구간 선택
  → 질문과 검색 자료를 학교 LLM에 전달
  → 분석·요약 답변 생성
  → 출처 번호 확인 후 실제 링크 연결
```

현재는 최대 3개의 검색 결과를 사용합니다. 본문에서 질문의 키워드가 포함된 구간을 우선 선택하고, 전달하는 내용은 출처당 최대 1,400자로 제한했습니다. 본문을 가져오지 못하면 검색 발췌문을 사용합니다.

LLM에는 확인된 사실과 기사에 나온 해석을 구분하고, 자료들의 공통점과 차이를 정리하도록 지시했습니다. 출처 URL은 모델이 직접 만들게 하지 않고 서버가 실제 검색 결과에서 연결합니다.

다만 출처 번호가 맞다고 해서 답변 내용까지 정확하다는 뜻은 아닙니다. 인용한 자료가 답변의 주장을 정말 뒷받침하는지 자동으로 검증하는 기능은 아직 없습니다. 중요한 수치나 사건은 원문도 함께 확인해야 합니다.

자체 벡터 DB나 임베딩 모델은 사용하지 않았고, 모델을 직접 학습하거나 파인튜닝하지도 않았습니다. 일반 설명과 자료 조사 모두 같은 학교 LLM 설정을 사용하며, 요청 모델명은 `OpenAI:Model`에서 읽습니다.

## 개발하면서 신경 쓴 부분

- **주문 가격:** 사용자가 임의의 가격으로 주문하지 못하도록 서버에서 가격을 가져옵니다.
- **거래 저장:** 잔액, 보유종목, 거래내역을 한 트랜잭션으로 처리해 일부만 반영되는 상황을 막도록 했습니다.
- **중복 주문:** 같은 주문번호가 다시 들어오면 기존 거래를 확인해 중복 체결을 방지합니다.
- **API 호출:** 시세 캐시와 호출 간격 제한을 두어 불필요한 외부 요청을 줄였습니다.
- **비밀 설정:** 외부 API 키와 DB 비밀번호는 클라이언트에 넣지 않고 서버 설정에서 관리합니다.

## 실행 방법

Windows, .NET 8 개발 환경과 MySQL 8이 필요합니다. Visual Studio에서는 ASP.NET 및 Windows 데스크톱 개발 도구를 준비한 뒤 `MockInvestment.sln`을 열면 됩니다.

### 1. 소스 내려받기

```powershell
git clone https://github.com/hhhuuu3583/InvestmentCompass.git
cd InvestmentCompass
```

### 2. DB 준비

기본 테이블인 `users`, `accounts`, `stocks`, `holdings`, `trades`가 필요합니다.

**현재 저장소의 SQL은 전체 DB 초기화 파일이 아니라 기존 DB에 대회 기능을 추가하기 위한 파일입니다.** 처음 실행하는 환경이라면 기본 테이블을 별도로 준비해야 합니다.

- [00_preflight.sql](database/00_preflight.sql): 기존 테이블, 컬럼, 인덱스 확인
- [01_add_competitions.sql](database/01_add_competitions.sql): 필요한 경우 회원 권한 컬럼과 대회 테이블 추가
- [02_admin_role_example.sql](database/02_admin_role_example.sql): 관리자 계정 지정 예시

실행 전에 대상 DB와 기존 구조를 확인해야 합니다. 이미 있는 테이블의 누락 컬럼까지 자동으로 수정해 주는 스크립트는 아닙니다.

### 3. 서버 설정

Visual Studio에서 `MockInvestment.Api`를 우클릭하고 **사용자 비밀 관리**를 열어 아래 값을 설정합니다.

| 설정 | 내용 |
|---|---|
| `ConnectionStrings:MySql` | MySQL 연결 문자열 |
| `Jwt:Issuer`, `Jwt:Audience`, `Jwt:SecretKey`, `Jwt:ExpiresInMinutes` | 로그인 토큰 설정 |
| `Kis:BaseUrl`, `Kis:AppKey`, `Kis:AppSecret` | KIS 연결 정보 |
| `QuoteCache:Seconds` | 현재가 캐시 시간 |
| `OpenAI:BaseUrl`, `OpenAI:ApiKey`, `OpenAI:Model` | 학교 LLM 연결 정보 |
| `Tavily:ApiKey` | Tavily 검색 키 |

일부 기본값은 `appsettings.json`에 있습니다. JWT 비밀키는 최소 32바이트의 무작위 키를 Base64로 인코딩한 값을 사용합니다. 실제 키와 비밀번호는 GitHub에 올리지 않습니다.

AI 답변은 학교에서 제공하는 API를 통해 생성합니다. 서버 주소는 https://aikey.wsu.ac.kr이며, /api/v1/chat/completions로 요청을 보냅니다. 코드의 설정 이름은 OpenAI이지만 실제 요청은 학교 API 서버로 전달됩니다. 모델명과 API 키는 계정에서 사용할 수 있는 값으로 설정해야 합니다.

### 4. 서버와 클라이언트 실행

```powershell
dotnet restore MockInvestment.sln
dotnet build MockInvestment.sln
dotnet run --project MockInvestment.Api --launch-profile https
```

서버가 켜진 상태에서 다른 터미널을 열어 클라이언트를 실행합니다.

```powershell
dotnet run --project MockInvestment.Client
```

클라이언트의 기본 서버 주소는 `https://localhost:7090/`입니다. 개발 환경에서는 `https://localhost:7090/swagger`에서 API를 확인할 수 있습니다. HTTPS 개발 인증서 설정이 필요할 수 있습니다.

현재 일반 계좌 주문은 `Development` 환경에서만 허용됩니다. 관리자 계정은 DB의 `role`을 `Admin`으로 지정하고 다시 로그인해야 합니다.

## 아직 부족한 점

- 본문을 가져오지 못하거나 관련 없는 자료가 검색되면 AI 답변도 충분하지 않을 수 있습니다.
- 키워드로 본문을 선택하기 때문에 기업명 표현이 다르거나 문맥이 긴 경우 중요한 내용을 놓칠 수 있습니다.
- AI는 계좌 DB를 자동으로 읽거나 사용자를 대신해 주문하지 않습니다.
- 외부 API의 사용량과 요청 제한 때문에 응답이 지연되거나 실패할 수 있습니다.
- 실제 거래소의 호가 매칭, 부분 체결, 수수료와 세금은 반영하지 않았습니다.
- 새 환경에서 바로 실행할 수 있도록 전체 초기 DB 스키마를 정리하는 작업이 남아 있습니다.

앞으로는 기사별 근거를 따로 정리하고, 답변과 인용한 내용이 맞는지 확인하는 부분을 개선하고 싶습니다. 검색할 때 기업과 기간을 더 정확하게 반영하고, API 오류 안내도 보완할 계획입니다.

## 라이선스

프로젝트 라이선스는 아직 정하지 않았습니다. 팀에서 논의한 뒤 추가할 예정입니다. 외부 API와 데이터 사용에는 각 서비스의 이용 조건이 적용됩니다.
